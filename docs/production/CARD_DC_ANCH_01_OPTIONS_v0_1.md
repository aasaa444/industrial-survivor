### 独立像素差异验证（vision_pixel_diff，original=v0.1, rebuilt=v0.2, threshold=16）

- **总体差异**：`diffRatio = 37.58%`（886,529 / 2,359,296 像素差异）。这高于"仅右侧 B2 局部细化"的严格像素期望（右面板约 1/3 + 过渡区），说明既有"localized right-side"在**构图/语义上成立但并非逐像素锁定右栏**——存在跨栏到中央附近的次级变化，无法从静态像素差异证明左栏/中栏逐像素未变。
- **最差区域分布**：最差 5/5 个 256×256 网格全部位于 `x∈[1536,2048]` 右栏（ratio 0.9268–0.9997），且集中于 y∈[288,864]（中上部）与 y∈[720,864]（中下部）——即 B2 光场主体区域。这**佐证了"主要变更集中于右侧 B2 区域"**，与 ANCHOR_REVIEW_v0_2.md §10.3 的"构图意义/敌群家族/环境连续性保持、不能证明逐像素未改"立场一致。
- **含义**：像素证据既支持"右侧收敛真实发生"，也保留了"左/中栏非逐像素不变"的不确定性——两种都不被静态观察推翻，如实保留。

### 唯一创意 verdict（与既往复审一致）

**`recommend-revision`**：v0.2 已在用户指定方向（右侧 B2 环/粒子/余辉面积亮度收敛、保留核心→过渡→衰减）上部分满足并明显缓解，且未观察到 rusted-industrial + restrained cyan 方向漂移；但静态图中右侧仍主要读为较宽半透明圆形残留场，敌潮成片移除/连续清除通道/玩家负空间尚未充分成为第一结果，玩家保持最高优先级剪影也无法从静态图充分证实。因此**本 Director 不把 v0.2 接受为新视觉基线**；v0.1 的用户接受状态保持不变。本 verdict 仅创意复审，不替代 QA、运行时或最终审美验收。

## 选项（4 个，精准、互斥）

### Option 1 —「保持 v0.1 基线，v0.2 维持候选（暂不推进）」

- **名称**：保持 v0.1 用户接受基线；v0.2 继续作为未接受候选，本轮不推进任何版本化修订。
- **依据**：ANCHOR_DECISION.md 记录 v0.1 为用户接受静态基线、v0.2 为未接受候选且不得静默替换（§32/§48）；本 Director 独立观察（v0.1/v0.2）均未观察到方向漂移，但 v0.2 清除成果仍未充分成为第一结果，`recommend-revision` 成立；开发者当前处于 `development governance / kickoff readiness preparation`、实现 `NOT_AUTHORIZED`，无生产资产引入压力。
- **影响**：
  - 产品：视觉基线明确，短期无基线变更承诺；风险为零升级。
  - 创意：保留当前静态方向锚点；`recommend-revision` 未了结的改进作为未来版本化修订候选留存，不静默丢弃。
  - 技术：无需 Technical Art / 2D Artist 变更资产方向；对 kickoff readiness 的 Anchor 输入保持现状。
  - 范围：最小；不新增修订/生成动作。
  - 进度：不阻塞；DC-ANCH-01 以"维持 v0.1"闭环，其余 Gate 继续按静态复审推进。
- **风险**：视觉方向改进被推迟；但本轮无生产资产依赖 v0.2，推迟不构成实际损失。回滚成本 ≈ 0（未改变任何基线/资产/合同）。验证成本：无需验证（决策即闭环）。

### Option 2 —「升级 v0.2 为新基线（采纳候选为新 accepted baseline）」

- **名称**：把 `anchor_core_v0_2.png` 提升为新的用户接受视觉基线，替换 v0.1。
- **依据**：v0.2 在右段面积/亮度/余辉/粒子密度上实质收敛，方向更接近"受控残留"，且未观察到风格漂移（本会话独立观察 + ANCHOR_REVIEW_v0_2.md §10.3）。
- **影响**：
  - 产品：视觉基线改变，影响后续 Technical Art / 2D Artist 资产方向输入（cr-301 记录："若选 v0.2 → 影响后续资产方向"）。
  - 创意：**与本 Director 唯一 verdict（`recommend-revision`）相悖**——本卡陈述该候选未充分解决清除成果/玩家优先级，若仍升级属于用户越过 Director 建议的自主审美裁决（用户有权，但本卡如实标注风险）。
  - 技术：资产/装饰/光照方向依 v0.2 调整；需更新 STYLE_MANUAL / 资产契约方向引用。
  - 范围：升级触发广泛下游引用更新（UX §10、Charter §Anchor 条款、资产/风格文档）。
  - 进度：变更下游方向引用需一次同步更新，属可控但真实工作项。
- **风险**：接受了一个静态图中最弱项（清除通道/玩家优先级）尚未解决的候选作为基线，可能把该薄弱处固化到后续资产方向；偏离 Director 建议。回滚/验证成本：可回滚（v0.1 文件仍保留、基线记录可改回），但已由下游资产/风格文档做出的方向引用调整需反转；`reauthorize_charter` 判定见决策后记录规则。

### Option 3 —「v0.2 定向修订后再定（授权一次明确版本化的 v0.3 局部修订）」

- **名称**：在用户另行授权下一次明确版本化的局部修订（v0.3）后复审，届时再决定基线。
- **依据**：本 Director `recommend-revision` 的未了结项是**可定位的局部问题**（右侧圆形残留场仍偏大、敌潮成片移除/连续通道/玩家负空间未充分成为第一结果）——不是方向性问题；ANCHOR_REVIEW_v0_2.md §7 / §10.6 已明确"下一步交由用户决定是否另行授权一次明确版本化的局部修订"；这与 v0.1→v0.2 已证明的"单次授权 refinement 可达局部收敛"路径一致。
- **影响**：
  - 产品：视觉基线维持 v0.1；v0.2 仍为候选；v0.3 为下一次修订候选。
  - 创意：直接回应 `recommend-revision` 的剩余项，把"清除成果/玩家负空间"设为 v0.3 的验收目标。
  - 技术：仅一次独立版图像编辑（视觉生产成员执行）；不涉及 Godot / 运行时。
  - 范围：一次有界的版本化修订授权；须用户另行明确授权（本卡不构成授权），不开放无界探索。
  - 进度：引入一个新的小版本化修订/复审/决策循环，占用一次治理窗口。
- **风险**：多一次迭代；若 v0.3 仍不达标准，可能落入迭代疲劳——因此需**预定义 v0.3 的静态验收判据**（清除通道连续开阔、玩家负空间明确、无持续发光场）来判定"到/不到"。回滚/验证成本：产生一次新候选图与一次独立复审；v0.1/v0.2 均保留，无破坏性。

### Option 4 —「推迟复审（Defer）：v0.1 维持基线，DC-ANCH-01 本轮不闭环，待运行时/早期资产方向确定后再判」

- **名称**：推迟本卡的基线裁决；Anchor 决策留到有运行时证据或确定的早期资产方向节点再处理，期间 v0.1 维持基线。
- **依据**：本卡证据全程为 `synthetic/anchor` 静态图，而 Anchor 的最终价值在于引导**运行时**可读性/清除结果/玩家优先级（UX §10、Charter §274）；当前处于 governance/readiness、实现未授权，无生产资产依赖 v0.2；`recommend-revision` 的剩余项只有运行时证据能真正证伪/证实"清除通道/玩家优先级"。
- **影响**：
  - 产品：视觉基线维持 v0.1；基线裁决暂缓，不形成 v0.2 方向承诺。
  - 创意：把剩余改进的可靠裁决从"静态迭代"移至"有运行时早期资产时可证实的阶段"，更符合证据纪律。
  - 技术：Asset 早期 placeholder / 场景方向可先按 v0.1 + `recommend-revision` 的已知约束（克制光、优先玩家/空地问）执行，无需等待基线确定。
  - 范围：本卡不闭环即占位；不新增版本化修订/生成动作。
  - 进度：把决策窗口让给更高优先级 gate；本卡保持 `unresolved` 顺延（决策窗口总规则 §7 第 1 条：错过窗口保持 unresolved、绝不静默通过）。
- **风险**：基线未定造成早期资产方向引导延迟；但因 Anchor 本质是静态引导层、且实现未授权，实际风险低。回滚/验证成本 ≈ 0（未改变任何基线/资产；后续在任意治理窗口以新卡重新制备选项）。

## 专业推荐（唯一）

**推荐 Option 1 ——「保持 v0.1 基线，v0.2 维持候选（暂不推进）」**，同时把 `recommend-revision` 的剩余项（清除通道/玩家负空间/无持续发光场）登记为未来版本化修订候选。

**一句理由**：在实现与生产资产均未授权、且 Anchor 的最终价值只能在运行时验证的当前 governance 阶段，过早推进一个静态图最弱项尚未解决的候选（升级 v0.2）或再开一轮静态迭代（v0.3）都不划算——保留已收敛的 v0.2 作为开源候选、维持 v0.1 基线，既不冒险固化薄弱处，也保住了已获得的收敛成果。

**异议（并列，供用户知情，不擅自消解）**：
- 若用户审美上**已可接受** v0.2 的收敛（即便清除成果未完全成为第一结果），Option 2 亦合理——但本卡如实标注其与本 Director `recommend-revision` 相悖，且是用户自主审美裁决。
- 若用户更看重**尽快得到可静态定稿的 Anchor 方向**而非证据完备性，Option 3（v0.3 定向修订）提供更快收敛路径——但需多一次迭代窗口。

**依赖（并列）**：
- **Technical Art / 2D Artist 资产方向**：依赖本卡基线结论——升 v0.2 或修订会改变后续资产 brief 的视觉参照（cr-301 记录）；v0.1 维持则资产方向不变。
- **UX §10 Anchor boundary**（`KICKOFF_UX_UI_CONTRACTS_v0_1.md` §10/§228）：任何"把 v0.2 当已接受"或改变已接受基线的主张，UX 合同都要求 escalate 到用户；本卡即该升级入口。选 Option 1 时 UX §10 无需变更；选 2/3 需同步更新其引用。
- **Development Charter §Anchor baseline clause**（`DEVELOPMENT_CHARTER_DRAFT_v0_1.md` §Anchor 条款/§366）：v0.1 是 Charter 记录的静态预生产基线；v0.2 为未接受候选；任何替换需单独用户决定。选 2 会触发该条款引用更新。

**候选预算相关**：本卡不涉及六项候选预算或 1280×720 红线；无任何数值门槛提升。
