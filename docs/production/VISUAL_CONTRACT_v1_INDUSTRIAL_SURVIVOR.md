## 玩家画面承诺

首屏不是调试沙盘。它必须读成一台正在失控的工业战斗系统：角色是青色能量信号，敌人是锈红威胁，玩家在深色钢铁信息层中掌握生命、时间、成长与构筑。

## 完成级 UI 规则

- HUD 只能由有背景、边界、内边距的容器构成；不允许裸 Label 贴在地图上。
- 经验条为固定像素高度的 ProgressBar，而不是字符条；累计经验永远不能改变其宽度。
- 每张升级卡必须有独立层：稀有度边框、图标/图形锚点、标题、能力分类、结果描述、输入提示。
- 单一焦点：升级窗口打开时，背景压暗、玩家仍保持可见、卡片是唯一高对比区域。
- 暂停与结果共享同一控制台式覆盖层；结果不显示内部 id，例如 `pierce`。
- 目标窗口：1280x720、1600x900、1920x1080；容器随 viewport 锚定、不可溢出。

## 世界构图规则

- 玩家始终有脚下暗影/能量底盘和高对比轮廓。
- Walker/Brute 使用锈红危险边缘，不与背景锈色融为一体。
- 青色攻击线仅在真实命中周期内可见；不能成为长期屏幕噪声。
- 能量核心的明度高于背景、低于升级奖励。
- 画面每个时刻只允许一个最高亮焦点：升级 > Boss/结果 > 命中 > HUD 交互 > 环境。

## 60–90 秒垂直切片检查表

- 主菜单/开始层存在；
- HUD：生命、等级、构筑、目标时间、经验条可读；
- 三卡和单卡升级均居中、状态完整、无溢出；
- Rail/Fan/Pulse 区别可从一帧读出；
- 暂停/结果/重开视觉一致；
- 无 debug 字段、裸 Label、默认灰按钮、裸进度文本或内部状态名；
- 真实窗口截图在三种分辨率通过视觉检查。
