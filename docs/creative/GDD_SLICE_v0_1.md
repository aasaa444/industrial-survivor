## 2. 产品定义与体验目标

### 2.1 产品定义

这是一个忠实幸存者流的 PC-first Demo / Vertical Slice：玩家以简单、直接的移动，在单屏有界工业场地中面对持续汇聚的锈蚀人形群；定向能量弧自动攻击，玩家通过走位影响下一次攻击结果。首个 Slice 只证明一个可重复、非惩罚性的 8 分钟清屏体验。

- **玩家角色：** `废土清除员`（`user_confirmed`）。
- **普通敌人：** `锈蚀人形群`（`user_confirmed`）；单一普通敌人家族。
- **基础攻击：** `定向能量弧`，用户确认的表现目标为中短程单弧刃，约 `90°`、射程约玩家宽度 `2–3 倍`；这些约略描述不是已调定运行时常数。
- **视角与场地：** 固定斜俯视、单屏有界工业场地（`user_confirmed`）；尺寸、障碍、装饰和布局仍未决。
- **平台窗口：** PC-first；设计基准 `16:9`，支持常见宽屏并设置最小可读性红线；不承诺手柄。

### 2.2 玩家承诺

> 用简单直接的移动和自动攻击切穿敌潮，看到越来越夸张但仍清晰的清屏胜利，获得有重量、可重复、非惩罚性的解压体验。

创意读法是让玩家看到从压力到控制的空间变化，而不是用更亮、更大、更多粒子或更多敌人单独定义爽感。

### 2.3 体验支柱

1. **清屏支配：** 敌潮从可读压力变成可读的连续清除结果；空间结果优先于计数器或纯特效。
2. **移动中的主动控制：** 移动用于选择路线、保留可移动空间，并影响下一次自动攻击。
3. **可见的同源力量跃迁：** 穿透先改变同一弧刃的命中结果，扇裂再扩展为中央加左右三道弧，保持同源连续性。
4. **短促释压、非惩罚节奏：** 压力存在但必须保留可恢复通道；失败轻量、立即再试。

### 2.4 创意非目标与严格上限

首个 Slice 上限为：1 个玩家、1 个普通敌人家族、1 个攻击家族、1 个 B2 组合、1 个单屏工业场地、8 分钟、最小 HUD、一次性移动提示。明确排除：Boss、精英、第二场地、完整叙事、额外武器/敌人家族、完整 UI、O2 局外构筑收藏、局外成长/货币、复杂复盘和长期系统。

不以环形攻击规则、持续光场、特效规模、亮度、粒子数或敌人数替代可读的玩家/危险/敌潮/通道结果；`anchor_core_v0_1.png` 不是最终资产，也不是运行时证据。

## 3. Slice 目的、最小证明对象与会话结构

### 3.1 最小证明对象

本 Slice 要让未来观察能够检验以下设计假设，而不是证明已实现：

`压力 → 可读命中 → 敌潮下降/通道恢复 → 穿透 → 扇裂的同源力量跃迁 → 8 分钟控制权完成`

需要暴露的最小真相：玩家能理解移动；自动攻击在移动中形成可读循环；敌潮清除改变空间；两次固定升级产生可见且仍清晰的 B2；胜利和失败都支持立即再试。

### 3.2 8 分钟会话结构

以下是设计结构，不是已平衡的时间表；具体阶段时间、密度和阈值标为 `team_proposal` / `unresolved`。

1. **进入战斗：** 建立玩家、单屏场地、敌潮与最小 HUD；一次性移动提示立即出现。
2. **进入压力：** 锈蚀人形群从边缘/远端持续进入并向玩家汇聚；玩家首次有效移动后提示淡出。
3. **自动攻击循环：** 每次发射前刷新最近威胁集群，发射后本次目标固定；命中与击杀反馈短促分层。
4. **持续包围：** 通过移动保留通道；局内经验/碎片仅作为两次升级的中介。
5. **第一次保证升级：** 完全暂停，出现 3 张同关键词穿透变体卡，选择 1 张；反馈后恢复。
6. **路线压缩：** 压力增强但保持可恢复通道；三阶段读法为进入压力→持续包围→路线压缩。
7. **第二次保证升级：** 完全暂停，出现 3 张同关键词扇裂变体卡，选择 1 张；中央弧保留并向左右展开为三道弧，三弧继承穿透且各自独立计数。
8. **B2 清屏：** 敌潮密度下降、可移动通道变宽是主要结果；不以持续光场作为结果。
9. **终点：** 存活至 8 分钟计时结束即胜利；胜利或失败先显示短暂清晰结果，然后自动立即重开，无局外损失。

## 4. 系统规则与状态转换

### 4.1 核心决策链

| 环节 | Slice 规则 | 状态变化 | 玩家可见反馈 | 下一决策 |
|---|---|---|---|---|
| 意图 | 保留空间、接近目标或离开危险 | 玩家选择方向 | 玩家位置与最近危险持续可读 | 继续走位或等待攻击结果 |
| 输入 | `WASD + 方向键`，只有移动，无冲刺/闪避 | `moving` / `idle`（规范中性命名；历史 `combat_moving` / `combat_idle` 为 alias，仅用于追溯，不另增产品状态） | 玩家移动；边界限制待定 | 选路线与移动口袋 |
| 自动攻击 | 发射前刷新最近威胁集群，发射后本次目标固定 | `attack_target_locked` | 单弧命中、后仰、击杀塌缩消散 | 观察清除结果并调整位置 |
| 受击 | 接触造成单次伤害，玩家与敌人短促轻微分离；三段生命并有短暂无敌 | `hit` → `invulnerable`；生命耗尽转 `defeat` | 暖色轮廓闪烁；生命变化 | 脱离危险、恢复通道 |
| 成长 | 经验/碎片只服务两次升级 | 达到阈值 → `upgrade_pause_1/2` | 完全暂停、三列卡 | 在同关键词内选择 |
| B2 | 第一次穿透，第二次扇裂；三弧各自独立计数 | `pierce_acquired` → `fan_split_acquired` | 同源弧形覆盖与清屏结果 | 利用更宽通道继续控制 |
| 终局 | 存活至 8 分钟 | `victory`；生命耗尽为 `defeat` | 结果优先、短暂清晰 | 自动立即重开 |

### 4.2 状态机（设计基线）

- `reset` → `run_entry` → `combat_active`：重置本局状态，生成玩家、场地与敌潮；不保留局外资源。历史 `run_init` / `run_reset` 仅作为 alias 追溯，不另增 canonical gameplay 状态。
- `combat_active` → `moving` / `idle`：仅由移动输入改变；无冲刺、闪避或其他移动能力。历史 `combat_moving` = `moving`，历史 `combat_idle` = `idle`。
- `combat_active` → `attack_cycle`：`attack_cycle` 是 gameplay lifecycle 的父状态/一次攻击周期；进入周期后，在发射前刷新目标。
- `attack_cycle` → `attack_target_locked`：目标刷新完成后进入该瞬时子状态；`attack_target_locked` 是 `attack_cycle` 的 canonical 子状态，不是独立的并行攻击生命周期。
- `attack_target_locked` → `attack_cycle`：完成本发发射并保持本发锁定目标直到本发结算；命中/击杀反馈及结算规则仍按未决攻击碰撞规则处理，结算后回到下一次 `attack_cycle`。
- `combat_active` → `hit`：敌人接触造成单次伤害并短促分离；受击后进入 `invulnerable`（确切时长未决）。
- `hit` → `invulnerable`：受击处理完成后进入短暂无敌。
- `invulnerable` → `combat_active`：无敌期间结束且玩家仍存活时显式回到战斗；无敌期间重复受击处理仍为 `unresolved`。
- `combat_active` → `upgrade_pause_1/2`：达到局内经验/碎片条件；两次升级保证出现且完全暂停；选择反馈后回到 `combat_active`。
- `combat_active` → `victory`：计时达到 8 分钟且玩家仍存活。
- `combat_active` → `defeat`：生命耗尽（具体每次伤害与死亡触发未决）。
- `victory/defeat` → `reset` → `run_entry`：短暂清晰结果后自动立即重开；无局外损失。
- 失焦/窗口变化：不应丢失升级选择或误确认；暂停、恢复和输入冻结细节为 `team_proposal` / `unresolved`，需后续 UX/工程设计。

**未决保持不变：** 无目标处理、多个同等最近目标的 tie-break、攻击间隔、锁定刷新细节、碰撞规则、命中上限与衰减等仍为 `unresolved`；本状态机不捏造任何数值。

### 4.3 规则失败、恢复与边界行为

| 规则 | 失败/异常情形 | 设计边界与恢复 |
|---|---|---|
| 移动 | 无输入、输入冲突、触及场地边界 | 玩家仍可观察攻击结果；边界缓冲与冲突优先级 `unresolved`，不得假定穿出边界 |
| 目标锁定 | 无目标、多个同等最近目标、目标离场 | 目标定义、tie-break、无目标处理和刷新时机细节 `unresolved`；不得制造不可解释追踪 |
| 攻击命中 | 重复命中、穿透上限、目标重叠 | 固定命中上限、后续轻度衰减、三弧独立计数为 `user_confirmed`；具体数值/重复命中为 `unresolved` |
| 接触 | 连续重叠、多人重叠、边界分离 | 接触为单次伤害并短促轻微分离；伤害间隔、分离距离、堆叠处理待提案 |

| 生命 | 短时间连续受击、无敌期间再次接触 | 三段生命与短暂无敌已确认；每次消耗、时长和重复处理 `unresolved` |
| 终局 | 胜负同时满足或重开清理不完整 | 终局优先级、状态清零清单和输入锁定待提案；产品要求结果短暂清晰后立即重开 |

## 5. 局内成长、B2、压力与轻随机

### 5.1 局内成长

经验/碎片只作局内中介，服务“清除敌潮 → 达成升级 → 观察 B2”；不形成货币、O2、商店、局外持久化或永久成长。来源、掉落/拾取、收集半径、阈值、进度表现、升级触发和重开清零均为 `unresolved`。

### 5.2 两次升级与同源 B2

- 第一次升级保证出现，3 张卡均为穿透关键词变体；选 1 张。
- 第二次升级保证出现，3 张卡均为扇裂关键词变体；选 1 张。
- 三列横向等宽卡，鼠标点击或方向键聚焦，`Enter/Space` 确认；无跳过、无重掷。
- 升级界面完全暂停；选择后先给已获得反馈，再恢复战斗。
- 穿透固定命中上限，后续命中轻度衰减；三道弧分别独立计数。
- 扇裂保留中央弧并向左右展开为三道弧，三道弧继承穿透。

以上结构是 `user_confirmed`；命中上限、衰减比例、弧精确角度/间距/长度、卡片文案、变体数值、随机池、反馈时长和恢复时序均未决。

### 5.3 波次压力与轻随机

压力三阶段读法固定为“进入压力 → 持续包围 → 路线压缩”，始终保留可恢复通道。内容只允许轻随机：结构、关键旅程、升级顺序和 `穿透 → 扇裂` 固定；随机种子、进入点、随机范围、可复现性和极端样本约束为 `unresolved`。不得通过随机破坏公平、阅读或两次升级保证。

## 6. UX/UI 设计基线

### 6.1 关键旅程

`进入战斗 → 提示移动 → 移动与自动攻击 → 受击/无敌 → 第一次穿透暂停升级 → 第二次扇裂暂停升级 → B2 清屏/空间恢复 → 8 分钟胜利或生命耗尽失败 → 短结果 → 自动重开`

**UX provenance:** 本节及 §§6.2–6.6 是 `static_design_input / no separate direct final report`：仅采用授权文档中的 `user_confirmed` UX 决定（最小 HUD、一次性移动提示、三列同关键词卡、鼠标/方向键、Enter/Space、完全暂停、失焦不丢选择、16:9/宽屏与基础可访问性）以及可接受的直接 UX 原则；不采用任何嵌套 UX 成员或嵌套 Doc Scribe/QA 产出作为证据。

### 6.2 信息层级与 HUD

HUD 优先级为：

1. 玩家、最近危险、可移动空间；
2. 三段生命、计时器、B2 关键词与阶段状态 `穿透 → 扇裂`；
3. 必要的局内经验/碎片中介。

HUD 不得遮挡玩家、敌潮、攻击结果或通道。字段、锚点、字号、颜色、图标、两格阶段样式和安全边距仍为 `team_proposal` / `unresolved`，不能由本文件假定。

### 6.3 移动提示

进入战斗立即显示极简功能文案；首次有效移动后淡出；每局只出现一次。最终句子、有效移动定义、语言版本、淡出时长、失焦和重开行为均未决。

### 6.4 升级卡与结果

三张同关键词变体卡横向等宽排列。鼠标 hover/click；方向键 focus；`Enter/Space` confirm。完全暂停，选择后显示短暂获得反馈再恢复；不得重掷或跳过。卡片具体模板、文案、图标、焦点样式和反馈时长未决。

胜利/失败先给短暂清晰结果，结果优先于装饰，随后自动立即重开；无货币、O2、复杂复盘或确认菜单。胜利表达控制权完成、短促释压；失败表达轻量中断、立即再试。

### 6.6 输入、响应式与可访问性

首个 Slice 支持 `WASD + 方向键` 移动；升级支持鼠标与方向键聚焦、`Enter/Space` 确认；不承诺手柄。以 `16:9` 为设计基准，常见宽屏优先扩展留白，不拉伸文字/卡片；最小分辨率、比例集合、缩放/黑边/裁切策略和字号均未决。

基础可访问性底线：状态不只依赖颜色；焦点有非颜色信号；反馈短促、不持续高频闪烁；文本对比与交互区域足够。精确对比度、字号、焦点尺寸、闪烁频率和动效减弱规则须后续提案并确认。

## 9. Provenance 与决策分层

### 9.1 当前有效 `user_confirmed`（来自 §13，22 项）

1. 只有移动，不加入冲刺/闪避；2. `WASD + 方向键`，首个 Slice 不承诺手柄；3. 每次发射前刷新最近威胁集群，发射后本次目标固定；4. 接触单次伤害并短促轻微分离；5. 胜利/失败短结果后自动立即重开、无局外损失；6. 穿透固定命中上限、后续轻度衰减、三弧独立计数；7. 三张同关键词变体卡形成同方向取舍；8. 升级完全暂停，选择反馈后恢复；9. 经验/碎片只服务两次升级，不是货币/O2/局外持久化；10. 压力三阶段为进入压力→持续包围→路线压缩且保留通道；11. 胜利为控制权完成、短促释压；12. 失败为轻量中断、立即再试；13. 结构固定、内容轻随机；14. ### 9.2 `team_proposal`

- 将 8 分钟拆为进入压力、持续包围、路线压缩与终局收束的可读结构。
- 使用有限状态名（如 `combat_active`、`attack_cycle`、`upgrade_pause`）帮助未来实现沟通。
- 以玩家/危险/敌潮/结果/通道作为 HUD 与视觉层级。
- 使用静态前/中/后比较与未来运行时观察来检验清屏与 B2，而非增加光效。
- 后续由 Tech/Systems 提出 PC-first 性能目标、峰值预算和确定性规则，再回用户确认。

这些是组织和验证设计的团队方案，不是产品决定。

### 9.3 `assumption`

- 熟悉的幸存者流仍可通过可见空间控制、清屏规模、击杀重量和同源 B2 形成可辨识的解压体验；目前未被运行时或玩家证据验证。
- 受控轻随机可以增加重玩差异，同时不破坏公平与可读性；需要后续观察。

### 9.4 `unresolved`

## 10. 风险、handoff 与下一阶段授权闸门

### 10.1 主要风险

- **特效替代结果：** B2 可能变成持续光场，遮挡玩家、危险或恢复空间。
- **熟悉感缺少辨识度：** 若清屏、击杀重量和 B2 控制变化不可见，Slice 只剩类型模仿。
- **压力变成不可逆锁死：** 若通道不保留，违背非惩罚节奏。
- **数值/算法漂移：** 将约略方向或团队推荐误写成硬常数会提前锁死调优。
- **证据过度声明：** 静态 GDD 不能证明可玩性、性能、玩家理解或 QA 通过。

### 10.2 Handoff

- **Game Director：** 维护玩家承诺、清屏支配、移动控制、同源力量跃迁、v0.1 Anchor 边界；未来创意结论需证据。
- **Systems / Tech：** 提出攻击间隔/伤害/目标算法、接触间隔/无敌时长、穿透上限/衰减、扇裂几何、经验阈值、波次具体数字、确定性与性能红线；所有数字先标提案，再回用户确认。
- **UX/UI：** 将关键旅程、状态矩阵、HUD 层级、键鼠路径、失焦保护、16:9/宽屏与基础可访问性变成可评审方案；不自定未决产品规则。
- **Producer：** 当前只有 preproduction GDD 基线；不得据此承诺里程碑、资源或正式生产。
- **独立 QA / Release：** 未来依据第 8 节建立独立验收，实施者不得自我认证；当前没有 QA 结论。

### 10.3 下一阶段闸门

1. Tech/Systems 提交数值、算法、性能与实现约束提案；用户确认超出当前决定的产品/范围/平台/架构风险。

3. Charter 生效后，Producer 才能进入正式开发治理；Godot、代码、场景、资源、构建、运行、测试、QA 和发布分别遵循对应角色授权。
